# RAG document assistant with citations (Claude API + offline mode)

Ask questions about a folder of documents (`.md`, `.txt`, `.pptx`) and get a
short answer where **every fact cites its source**. The answer is generated by
Claude when an API key is set; without one it falls back to an offline
extractive answer, so the tool always works.

```
question ─▶ BM25 retrieval (own implementation) ─▶ top-k chunks, numbered [1]…[k]
                                                    │
                    Claude (claude-opus-5-5) ◀──────┤ ANTHROPIC_API_KEY set
                    offline extractive     ◀────────┘ no key / API error
                                                    │
                    answer + citation check (every [n] must point to a real source)
```

## Design choices

| Part | Choice and reason |
|---|---|
| Chunking | Markdown split on headings, then 180-word windows with 40-word overlap. PowerPoint: one chunk per slide, read directly from the slide XML (no extra dependency). Code blocks are not split on `#` lines. |
| Retrieval | **BM25 written from scratch** (k1 = 1.5, b = 0.75), section titles indexed with the text, light suffix stemmer (optional) |
| Generation | Anthropic Python SDK, `claude-opus-5-5`, adaptive thinking, explicit `effort`, system prompt that demands citations and says "not in the sources" instead of guessing |
| Refusals | `fallbacks="default"` (server-side fallback beta): if the model declines, the API retries on a fallback model in the same call; the switch is reported to the user. A full refusal returns a clear message. |
| Failures | typed SDK errors (auth, rate limit, API status, network) → offline answer plus a note saying why |
| Verification | answers whose citation numbers point to no supplied source are flagged |

## Evaluation

`eval/questions.jsonl`: 20 questions about my three other projects (the
documents in `corpus/`), each labelled with the section(s) that hold the answer
and one key fact. Questions are paraphrased on purpose ("challenge" instead
of "nonce", "user id" instead of "uid") so that pure word matching is not enough.

**Retrieval** (33 chunks):

| Retriever | hit@1 | hit@3 | MRR |
|---|---|---|---|
| keyword overlap (baseline) | 0.45 | 0.70 | 0.59 |
| BM25 | 0.50 | 0.70 | 0.62 |
| BM25 + light stemming | 0.50 | **0.90** | **0.70** |

**Answers, offline extractive generator:** key fact present in 50 % of
answers, citations valid in 100 %. This is the baseline for the Claude
generator (`python -m eval.run_eval --generator claude`), which **I have not
run yet**, because I had no API key while building this.

What I learned from the misses:
- **Vocabulary mismatch is the main failure.** "For how many seconds does a
  challenge stay usable?" never finds the section that says "nonce (120 s)".
  Lexical retrieval cannot bridge synonyms; dense embeddings or LLM query
  rewriting would be next.
- **Stemming is a trade-off, not a free win.** On my eval set it lifted hit@3
  from 0.70 to 0.90. On my DevOps course slides (217 slides, indexed locally
  only), it made "What is the difference between a Deployment and a Pod?" rank
  a `git diff` slide first, because "differences" now matches "difference".
- **The evaluation is optimistic.** I chose stemming after looking at these
  same 20 questions, and I wrote the questions myself with the documents in
  view. A held-out set written by someone else would be the honest next step.
- The extractive generator finds the right chunk but often quotes the wrong
  sentence (it missed "fail closed" while citing the right table). This is the
  gap the LLM is supposed to close, and it can now be measured.

## Tests

`pytest`: 12 tests. Four of them run the **real Anthropic SDK against a local
stub server**. They check that the request contains the model, adaptive
thinking, the effort level, `fallbacks="default"` and the beta header, and that
a fallback block, a refusal and a 401 error are each handled correctly. No API
key or network needed.

## Run it

```bash
pip install -r requirements.txt
python -m rag.cli "What happens when the revocation list cannot be fetched?"          # corpus/ by default
python -m rag.cli --corpus ~/my-slides "How does the HPA scale?"                      # any folder
export ANTHROPIC_API_KEY=...   # optional: answers generated by Claude
python -m eval.run_eval [--generator claude]
python -m pytest -q
```

Course slides or other documents you don't own: put them in `private/`
(ignored by git) and index them locally only.

## Why I built it

To practise integrating an LLM API into a real application: retrieval,
grounding, citations, failure handling and an evaluation that shows where the
system fails. These skills appear in AI and software engineering internship
offers that mention LLM APIs and Python.
